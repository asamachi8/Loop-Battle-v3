### 変更

- **駒をさらに2周り大きくした**
  - 絵柄 54 → **64ユニット**（PC表示で 53.7px → **63.6px**）
  - 選択リング 31 → **33**、突撃マーク 33 → **34.5**
  - **ループ入口の輪（28）は駒より内側になり、駒が乗ると隠れる**ようになった。
    駒を大きく見せることを優先した判断で、突撃できるかどうかは駒を選べばマークで分かる
  - 騎の名前（A1／B2）は font-size 12 → 11・y+37.5 に調整し、
    メダリオンどうしのすき間（11.8ユニット）に収まるようにした。縁取りも足した
  - 縦横に隣り合わせても駒どうしの重なりは0組（PC・スマホとも確認）

- **HPの数字を大きくし、背景のかすれ感を強めた**
  - 数字 11.5px → **15px**（PC実寸 14.9px）。絵柄からはみ出してよい扱いにした
  - 絵筆バッジを1.3倍に拡大し、位置を（+14,+14）→（**+18,+18**）へ
  - 輪郭を `feTurbulence` + `feDisplacementMap`（`lb-brush-rough`）でずらし、
    絵の具がかすれた縁にした
  - 毛の間が抜けたスジ（`BRUSH_STREAKS`、破線の細い線4本）を塗りの上に重ねた
  - 描画コストは1回あたり約7ms（20回の平均）で、操作感に影響なし

- **駒をさらに大きくし、周囲のリングも合わせて広げた**
  - 絵柄 48 → **54ユニット**（PC表示で 47.7px → **53.7px**）
  - ループ入口の輪 30 → **28**、選択リング 28 → **31**、突撃マーク 30 → **33**
  - 騎の名前（A1／B2）の位置を y+36 → **y+38** に下げた
  - 交点の間隔は70ユニットなので半径35が上限。
    メダリオン24.6 < 入口の輪28 < 選択リング31 < 突撃マーク33 < 上限35 の順に整理した
    （駒どうしの重なり0組を確認済み）

- **駒の絵柄を、重複ありで自由に選べるようにした**
  - 「同じ絵柄を選んだら2騎で入れ替える」動作を廃止し、**重複を許す**方式へ変更
  - 6種類のどれを何騎に使ってもよい（同じ絵柄を3騎そろえてもよい）
  - **相手側の3騎も同じように選べる**（相手と同じ絵柄になっても構わない）
  - 同じ絵柄が並んでも、駒の下の記号（A1／B2 など）で区別できる
  - 保存値の検証も重複を許す形に緩めた（実在するキーかどうかだけを見る）

- **駒の絵柄を大きくし、陣営のフチを細くしてぼかした**
  - 絵柄を直径40 → **48ユニット**に拡大（PC表示で 39.7px → **47.7px**）
  - フチは太さ6の実線から**太さ2.4＋ガウスぼかし**（`stdDeviation` 1.2）へ変更。
    メダリオンの外側に色が分かる程度の淡い縁取りとして残り、絵柄の面積を取らない
  - 寸法の定数を `PIECE_ART_R` / `PIECE_RING_R` / `PIECE_RING` / `PIECE_R` に整理した

- **HPを駒の右下へ移し、絵筆でひと塗りした背景にした**
  - 位置は駒の中心から右下（+12, +12）、傾き -28度
  - 背景は陣営の色で塗った絵筆の形（`src/ui.js` の `BRUSH_D`）。
    筆の毛の跡に見える明るいスジ（`BRUSH_HL_D`）を重ねている
  - 以前の「駒の下端の黒い丸バッジ」は廃止

- **駒の絵柄を画面上で入れ替えられるようにした**
  - 「駒のHP」枠の `騎A1` などの表示を**ドロップダウン**に変更。6種類から選べる
  - すでに他の騎が使っている絵柄を選ぶと、**その2騎で入れ替わる**（6種類が重複しない）
  - 騎の記号（A1／B2 など）は左端の小さなバッジとして残した
  - 選んだ組み合わせは `loopbattle.pieceArt` としてブラウザに保存する。
    壊れた値・重複した値が入っていた場合は既定の割り当てに戻す

### 実装上の判断

- 同期方式は「手を指した側が設定・盤面・ログをまるごと送り、受け取った側が置き換える」

  1手あたり数KBなので6駒のゲームでは通信量も問題にならない
- 同期処理（`net.js`）は通信手段に依存しない設計にし、`send` / `onMessage` を持つ
  オブジェクトを渡せば動くようにした。ループバック接続でブラウザ1枚でも検証できる
- `file://` で開いた状態では相手がURLを開けないため、その場合はオンライン対戦を
  開始せずに案内を表示する

### 実装上の補足（ルールに影響しない範囲の判断）

- ループ突撃はループを複数回通過してもよい（通過回数の上限なし）。
  同じ位置・同じ進行方向に戻った時点で経路探索を打ち切るため、無限ループしない。
- 経路探索中、突撃する騎自身の元の位置は「空いた交点」として扱う。
- 同じ敵へ複数の突撃経路がある場合、ノックバック方向が変わるため、
  プレイヤーが経路を選べるようにした（経路の1歩目に番号バッジを表示）。
- ループ突撃では通常接近攻撃は発生しない（§10 は「通常移動によって」と限定しているため）。
- ノックバック距離を2以上に設定した場合は、進める分だけ押し出して途中で停止する
  （盤外・駒に当たった時点で停止。連鎖押し出しは行わない）。
- 合法手が1つも無い場合に備え、パスボタンを用意した（通常は表示されない）。
- 技術構成：HTML + CSS + Vanilla JavaScript のみ。ビルド・依存パッケージ・サーバー不要。
  `file://` で直接開けるようにするため ES Modules ではなくクラシックスクリプトを使用。

### 既知の論点（Ver.0.2 以降の検討材料）

- 盤上の駒が6つと少ないためループ経路がほとんど塞がらず、**初手からループ突撃が成立する**。
  （本家 Surakarta は各24駒で経路を塞いでいる）。初期配置・駒数・ループ本数の調整候補。
- ランダム同士の自動対戦300回では、選べる行動のうち約19%がループ突撃だった。
  決着までの手数は中央値40手（各プレイヤー20回行動）。
