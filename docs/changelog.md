## Ver.0.3 — 2026-08-21 〜 08-25

オンライン対戦の追加。仕様書は `docs/specification_v0.3.md`。
**ゲームルールは Ver.0.2 から変更していない。**

### 追加

- **オンライン対戦（リアルタイム / 1対1）**（仕様書 §29）
  - 「対戦部屋を作る」で `?room=XXXXXX` 付きのURLを発行し、相手が開くと対戦開始
  - 担当（先攻・後攻）は部屋主が選べる。既定は部屋主が Player 1（青・先攻）
  - ブラウザ同士を直接つなぐ（WebRTC / P2P）。対局データは外部サーバーを経由しない
  - 接続の仲介にのみ PeerJS の公開ブローカーを使用
  - 通信ライブラリは `src/vendor/peerjs.min.js` として同梱し、
    オンライン対戦を開始したときだけ読み込む（ローカル対戦は従来どおり依存関係なし）
- **手番の制御**：自分の手番以外は盤面を操作できない。相手の手番中はその旨を表示する
- **設定の一本化**：対戦中はルール設定・盤面の種類・RESTART を部屋主のみが操作でき、
  変更は相手にも自動反映される。参加側の設定欄は無効化する
- **再接続**：同じ部屋URLを開き直すと、途中の局面から復帰できる
  （部屋を作った側のブラウザが開いている間）
- **切断通知**：相手が切断するとその旨を表示し、ローカル対戦に戻る
- `docs/deploy.md`：GitHub Pages への公開手順
- **GitHub 公開用パッケージ**（`Loop Battle Ver0.3 githubver` フォルダ）
  - リポジトリにそのまま置ける形に整えたコピー。`LICENSE`（MIT）・`.gitignore`・`.nojekyll` を追加
  - README をリポジトリのトップページ向けに書き直し（デモURL欄・公開手順・ライセンスを追加）
  - `docs/deploy.md` は GitHub Pages 専用の手順に統一（Netlify / Cloudflare Pages の手順は不使用のため削除）
  - ローカル作業用のURLメモ（`ループバトルプレイURL080816ver.txt`）は含めていない

### 追加（Ver.0.3 の対戦操作）

- **盤面左の手番表示**（仕様書 §20・§29.6）
  - 今どちらの番かを色・プレイヤー名で表示。オンライン対戦中は「あなたの番／相手の番」も出し、
    自分の番のときは枠を強調する。決着後は勝者と「あなたの勝ち／負け」を表示する
- **「盤面を最新に更新」ボタン**（オンライン対戦中のみ表示）
  - 相手へ最新の盤面を要求し、同時に自分の盤面も送る。通信が一瞬途切れて手が届かなかった
    場合の復旧用。プロトコルに `request-sync` を追加
- **先攻・後攻の選択**（部屋主のみ）
  - 「先攻（青）」「後攻（赤）」「ランダム」の3ボタン。ランダムは押した時点で抽選する
  - 担当は snapshot の `hostPlayer` で相手へ伝わる。参加側のボタンは無効化する
  - 対局中に変更した場合は確認のうえ対局を最初からやり直し、相手にも反映される
- **降参ボタン**（盤面下）
  - 相手の勝ちとして即座に決着。誤操作防止に確認ダイアログを挟む
  - ローカル対戦でも使える（現在の手番側が降参）。結果は盤面の状態として相手へ同期される
- **SNS共有ボタン**（LINE / X / メール / 端末の共有メニュー）
  - すべて新しいタブで開くため、**対戦ページを閉じずに**URLを共有できる
  - `navigator.share` に対応した環境では「端末の共有メニュー」ボタンも出る（ページ遷移なし）
- **リプレイ機能**（仕様書 §30）
  - 1手ごとに盤面のスナップショットを記録し、対局終了・RESTART・設定変更のタイミングで
    「戦歴」として**最大3対局**まで保持する
  - ログ欄に操作を追加：対局の選択（現在の対局＋直近3件／勝敗と手数を併記）、
    **▶ 再生**（0.7秒ごとに1コマ進む／再生中は ⏸ 一時停止）、**■ 停止**、**◀ ▶|** のコマ送り、位置表示
  - 再生中は盤面・ログ・手番表示・HP がそのコマの内容になり、盤面の枠とターン表示に印が付く
  - リプレイ中は盤面操作・降参・パスができない
  - オンライン対戦では相手から届いた盤面も記録するため、両者の手元に同じ記録が残る。
    相手のリスタートも対局の区切りとして扱う
  - 記録はページを開いている間のみ保持（保存機能は実装しない）
- **初期配置の指定を盤面のマス番号に統一**（仕様書 §6・§23）
  - デバッグ設定の表示・`src/config.js` の既定値ともに `26 27 28` / `9 10 11` の形式へ変更
  - 入力は従来の「行,列」形式（`4,1`）も引き続き受け付ける
- **ルール早見表をサイドパネルの先頭（オンライン対戦の上）へ移動**
- **ループ弧の進行方向マーク（▲）**（仕様書 §22）
  - 騎を選択している間、ループ突撃で通る弧の上に小さな▲を出し、どちら回りに進むかを示す
  - ▲は弧の中央にベジェ曲線の接線方向で配置する（幾何計算は `board.arcMarker()`）
  - 弧の色に合わせる（外周寄り＝黄／内側＝青）。経路ハイライト中はその経路の▲を明るくし、
    同じ弧に二重に描かないようにしている
  - 突撃が成立しない騎を選んでいるときは表示しない
- 通信プロトコルを v1 → **v2** に更新（`hostPlayer` の追加、`request-sync` の追加、
  退出メッセージを `resign` から `leave` に改名して降参と区別）

### 実装上の判断

- 同期方式は「手を指した側が設定・盤面・ログをまるごと送り、受け取った側が置き換える」
  全状態同期とした。差分同期をしないため盤面のズレが原理的に起きず、
  1手あたり数KBなので6駒のゲームでは通信量も問題にならない
- 同期処理（`net.js`）は通信手段に依存しない設計にし、`send` / `onMessage` を持つ
  オブジェクトを渡せば動くようにした。ループバック接続でブラウザ1枚でも検証できる
- `file://` で開いた状態では相手がURLを開けないため、その場合はオンライン対戦を
  開始せずに案内を表示する

### 検証

- ブラウザ2タブ間で実際にWebRTC接続し、**140ターンの1局を最後まで自動対戦**。
  両者の盤面・ログ・勝敗がすべて一致し、例外0件
- 盤面の種類とHPの変更が相手側の描画・入口表示・設定欄まで反映されることを確認
- 対局途中での再接続、切断通知、手番外の操作ブロックを確認
- ループバック接続による同期処理の単体確認（役割割り当て・状態同期・ログ同期・設定伝播・退出）
- リプレイの検証：コマ送り・自動再生・一時停止・停止（実盤面への復帰）、戦歴が3件で打ち止めになること、
  過去の対局が自分のログとともに再生されること、リプレイ中は操作できないこと、
  ループバック接続で両者に同じコマ数が記録され、相手のリスタートが対局の区切りになることを確認
- 進行方向▲の検証：▲が弧の曲線上（距離0.00px）に乗り、向きが実際の進行方向と一致すること、
  経路ハイライト中は明るい▲に切り替わり二重描画されないこと、盤面の種類を変えても追従することを確認
- 追加した4機能を実接続で確認：手番表示の切り替わり、盤面をわざとズラしてからの同期復旧、
  先攻後攻の指定（後攻を選ぶと参加側が先攻になる）・ランダム抽選・対局中の入れ替えと自動リセット、
  双方向の降参の反映、共有リンクが新しいタブで開く設定であること

### バックアップ（凍結）

- Ver.0.3 のこの時点の内容を、変更しない保存用コピーとして
  `Loop Battle Ver0.3 バックアップ 2026-08-25（変更禁止）` に保存した
  - `本体/` … 開発用プロジェクト一式（`loop-battle` の複製）
  - `GitHub公開用/` … リポジトリ公開用パッケージの複製
  - `MANIFEST.txt` … 全ファイルの SHA-256（後から中身が変わっていないか確認できる）
- 今後の変更はこのバックアップには反映しない。バリエーション展開の基準点として残す
- 誤って書き換えないよう、フォルダ内のファイルは読み取り専用にしてある

### 既知の制限

- 接続の仲介に公開ブローカーを使っているため、そのサービスが停止すると新規接続ができない
  （対局中の通信は影響を受けない）。自前の PeerServer に切り替えれば回避できる
- 会社・学校のネットワークや一部のモバイル回線では P2P 通信が遮断され、接続できない場合がある
- 不正防止は行っていない。相手側から送られてくる盤面をそのまま信頼する
- 観戦・再戦招待・レーティング・チャットは未実装

## Ver.0.2 — 2026-08-16

Ver.0.1 のプレイ結果を受けたルール改訂。仕様書は `docs/specification_v0.2.md`。

### 変更（ゲームルール）

- **初期配置を各騎1マスずつ前進**
  - P1：`(5,1)(5,2)(5,3)` → `(4,1)(4,2)(4,3)`
  - P2：`(0,2)(0,3)(0,4)` → `(1,2)(1,3)(1,4)`
- **ループ突撃にループ入口の条件を追加**（仕様書 §12）
  - ループ入口（そこから1歩でループ弧へ入る交点）に立っているときのみ突撃できる
  - 入口は盤面の種類ごとに変わる（種類1 は16地点、種類2 は4地点、種類3 は8地点）
  - 設定 `LOOP_ENTRY_MAX_STEPS`（既定1）で条件の緩さを変更でき、99 で Ver.0.1 の挙動に戻る
- **盤面を3種類から選べるようにした**（仕様書 §5）
  - 弧の指定を「交点の通し番号のペア」形式に変更し、`src/config.js` の `LB.BOARD_TYPES` に
    データとして定義。盤面を見ながら `[13, 33]` のように書けるので、新しい盤面は1件追加するだけで増やせる
  - 種類1「全隅ダブルループ」（既定）：弧8本・四隅に2本ずつ。一周24歩の回路が2つ（Ver.0.1 と同じ配置）
    `7-2 12-5 25-32 30-35`（黄） / `13-3 18-4 19-33 24-34`（青）／入口16地点
  - 種類2「対角2ループ」：弧2本。`4-24`（右上）と `13-33`（左下）。
    経路は一周せず、弧を1回通った先の行き止まりで終わる。入口4地点 `4 13 24 33`
  - 種類3「右上・左下ダブルループ」：弧4本。`12-5 25-32`（黄）と `3-18 19-34`（青）。
    4本とも一周せず、弧を1回通った先の行き止まりで終わる。入口8地点 `3 5 12 18 19 25 32 34`
  - 同じ隅に複数の弧がある場合、小さい方を内側（黄）・大きい方を外側（青）として描き分ける
  - デバッグ設定の「盤面の種類」プルダウンで、選んだ時点で切り替わる。
    現在の種類・弧の本数・入口の数は盤面の下に表示する
  - 3種類とも180°回転対称で、先手・後手の条件が等しい
- **ノックバックに連鎖押し出しを追加**（仕様書 §14）
  - 押し出し先に駒がある場合、その駒（および後ろに続く駒）をまとめて1マス押し出す
  - 敵味方を問わず巻き込む。設定 `CHAIN_KNOCKBACK` で無効化可能
- **壁激突ダメージを追加**（仕様書 §15・§16）
  - 押し出される列の先が盤端で詰まっている場合、押し出しの代わりに追加1ダメージ
  - ループ突撃3 ＋ 壁激突1 ＝ 最大4ダメージ。設定 `WALL_DAMAGE`（既定1）
  - 壁激突で撃破された場合、突撃した騎は対象の地点を占有する

### 追加（UI・デバッグ）

- ループ入口を薄い丸で常時表示（回路の色に対応。駒が乗っても見えるよう駒より大きい輪にした）
- **交点の通し番号（1〜36）を透かし表示**し、盤面下の「座標を隠す／座標を表示」ボタンで切り替えられるようにした
  - 番号は左上を 1 とし、左から右・上から下の順（`n = 行 × 6 + 列 + 1`）
  - 既定の初期配置は P1 = `26 27 28` / P2 = `9 10 11`
  - 表示位置は交点の右上。駒（半径22）に隠れない位置に置き、隣の交点と取り違えない距離を確保している
  - デバッグ設定の初期配置欄はこの通し番号でも指定できる（`26 27 28`）。従来の「行,列」形式（`4,1 4,2 4,3`）や両者の混在も受け付ける
  - デバッグ設定を適用して盤面を作り直しても表示・非表示の状態は維持される
- 視覚フィードバックに `WALL`（壁激突）と `PUSH!`（連鎖押し出し）を追加
- デバッグ設定に「壁激突ダメージ」「盤面の種類」「ループ入口までの歩数」「連鎖押し出し」を追加
- HP5 / HP6 を1クリックで切り替えて比較できるボタンを追加（仕様書 §27 D）
- `LB.app.game` / `LB.app.ui` をコンソールから参照できるようにした

### 修正

- ループ突撃の経路ハイライト表示中に盤面の種類変更やデバッグ設定の適用を行うと、
  古い盤面の弧IDを参照して例外が発生し、ターン表示が更新されないことがあった。
  盤面を作り直す際にハイライト・経路選択の状態を破棄するようにした

### 検証対象の変更

- HPの比較は **5 と 6 のみ**。HP3・HP4 は少なすぎるため候補から除外
- 通常攻撃ダメージ0の検証は行わない（騎のスキル導入時に改めて検討）

### 自動対戦による計測（ランダム同士）

HP5 と HP6 の比較（種類1・各300戦。旧「四隅ループ」盤での計測値）

| | HP5 | HP6 |
| --- | --- | --- |
| 決着までの手数（中央値） | 134手 | 147手 |
| ループ突撃が選べたターンの割合 | 23% | 25% |
| 突撃時に壁激突が起きた割合 | 6% | 10% |
| 突撃時に連鎖押し出しが起きた割合 | 2% | 6% |
| 未決着・例外 | 0件 | 0件 |

盤面の種類ごとの比較（HP5・各200戦）

| | 種類1 全隅ダブル | 種類2 対角2 | 種類3 右上左下ダブル |
| --- | --- | --- | --- |
| ループ入口 | 16地点 | 4地点 | 8地点 |
| 決着までの手数（中央値） | 102手 | 164手 | 164手 |
| ループ突撃が選べたターンの割合 | 37% | 6% | 12% |
| P1 勝 / P2 勝 | 94 / 106 | 95 / 105 | 101 / 99 |
| 未決着・例外 | 0件 | 0件 | 0件 |

弧が少ない盤面ほど突撃機会が減り、決着までの手数が伸びる。
Ver.0.1（＝種類1 かつ入口制限なし）は中央値40手だったため、
入口制限だけで手数は2.5倍、さらに弧を減らすと4倍になる。

### 仕様書の曖昧点について決めたこと

仕様書の記述だけでは一意に決まらなかった点を、確認のうえ以下のとおり実装しました。

1. **ループ突撃で敵が生存し、かつノックバックできなかった場合の突撃側の位置**
   （§18「敵の元の位置へ移動」と §15/§16 が両立しないケース）
   → 突撃側は**経路上、対象の1つ手前の交点で停止**する。ダメージは通常どおり3。
2. **通常移動で新たに複数の敵と隣接した場合**（§10 は「その敵騎1体へ」と読める）
   → **新しく隣接した敵全員**にそれぞれ 1 ダメージ。
3. **ループ弧で繋がった2交点（例：(1,0) と (0,1)）の扱い**
   → 通常移動・通常接近攻撃では**隣接として扱わない**（§9「通常経路」の解釈）。
   ループ弧はループ突撃専用の経路。なお弧をまたぐ至近距離のループ突撃は成立する。
4. **ループ経路の形状**
   → Surakarta 準拠の**弧8本**（四隅に2本ずつ）。簡易版（弧4本・1回路）は採用しない。

### 実装上の補足（ルールに影響しない範囲の判断）

- ループ突撃はループを複数回通過してもよい（通過回数の上限なし）。
  同じ位置・同じ進行方向に戻った時点で経路探索を打ち切るため、無限ループしない。
- 経路探索中、突撃する騎自身の元の位置は「空いた交点」として扱う。
- 同じ敵へ複数の突撃経路がある場合、ノックバック方向が変わるため、
  プレイヤーが経路を選べるようにした（経路の1歩目に番号バッジを表示）。
- ループ突撃では通常接近攻撃は発生しない（§10 は「通常移動によって」と限定しているため）。
- ノックバック距離を2以上に設定した場合は、進める分だけ押し出して途中で停止する
  （盤外・駒に当たった時点で停止。連鎖押し出しは行わない）。
- 合法手が1つも無い場合に備え、パスボタンを用意した（通常は表示されない）。
- 技術構成：HTML + CSS + Vanilla JavaScript のみ。ビルド・依存パッケージ・サーバー不要。
  `file://` で直接開けるようにするため ES Modules ではなくクラシックスクリプトを使用。

### 既知の論点（Ver.0.2 以降の検討材料）

- 盤上の駒が6つと少ないためループ経路がほとんど塞がらず、**初手からループ突撃が成立する**。
  （本家 Surakarta は各24駒で経路を塞いでいる）。初期配置・駒数・ループ本数の調整候補。
- ランダム同士の自動対戦300回では、選べる行動のうち約19%がループ突撃だった。
  決着までの手数は中央値40手（各プレイヤー20回行動）。
