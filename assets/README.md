# assets — 見た目にかかわる画像置き場

駒のデザインや盤面まわりの画像、デザインの参考資料をここに置きます。

```
assets/
├── pieces/      駒の画像（Player 1 / Player 2 の騎、撃破時の表現など）
├── board/       盤面まわりの画像（背景、盤の質感、ループ弧の装飾など）
├── ui/          画面部品の画像（HPアイコン、ボタン、ダメージ表示など）
└── reference/   デザインの参考画像（雰囲気・配色・レイアウトの見本）
```

`reference/` は**見て参考にするための置き場**で、ゲーム本体からは読み込みません。
実際にゲームで使う画像は `pieces/` `board/` `ui/` に入れてください。

---

## ファイルの置き方

- ファイル名は**半角英数字とハイフン**にしてください（例：`piece-p1.svg`）。
  日本語やスペースを含む名前は、公開先のサーバーによって読み込めないことがあります。
- 参考画像はファイル名で中身が分かるようにしておくと後から探しやすいです
  （例：`reference/board-atmosphere-01.png`）。
- 空フォルダは Git に登録できないため `.gitkeep` を置いてあります。
  画像を入れたら消して構いません。

## 駒の画像

**6枚とも実装済みです。** ゲームは `assets/pieces/` の Web用ファイル（176×176px）を読み込みます。

### 割り当て

**ゲーム画面の「駒のHP」枠にあるドロップダウンで、どの騎がどの絵柄を使うかを選べます。**

- 6種類のどれを何騎に使っても構いません（**同じ絵柄を3騎そろえてもOK**）
- **相手側の3騎も同じように選べます**（相手と同じ絵柄になっても問題ありません）
- 同じ絵柄が並んでも、駒の下の記号（A1／B2 など）で区別できます

選んだ組み合わせはブラウザに保存され、次に開いたときも同じです
（保存キー：`loopbattle.pieceArt`）。**見た目だけの設定なので、対戦相手には送りません。**
相手の画面では相手が選んだ絵柄で表示されます。

初期値は `src/config.js` の `LB.DEFAULT_PIECE_ART` です。

| 騎 | 陣営 | 初期の絵柄 | Web用ファイル |
| --- | --- | --- | --- |
| A1 | 青 | アメリゴ船長 | `fantasy-museum/amerigo.png` |
| A2 | 青 | シンガーアオスケ | `fantasy-museum/aosuke.png` |
| A3 | 青 | マルグリットメイド長 | `fantasy-museum/marguerite.png` |
| B1 | 赤 | ジェーンドゥ | `fantasy-museum/jane-doe.png` |
| B2 | 赤 | ツヅミサロン長 | `fantasy-museum/tsuzumi.png` |
| B3 | 赤 | ガイドあさまち | `fantasy-museum/asamachi.png` |

### フォルダの分け方

**コレクション1つにつきフォルダ1つ**です。

```
assets/pieces/
└── fantasy-museum/          コレクション「幻想肖像画美術館」
    ├── amerigo.png          ← ゲームが読み込む Web用（176px・各約65KB）
    ├── …（6枚・合計約400KB）
    └── original/            ← 元画像（1254px・各約2.5MB）。ゲームは読み込まない
        └── アメリゴ船長.png 他5枚
```

- **フォルダ名とWeb用ファイル名は半角英数字とハイフン**にします。
  公開先のサーバーによっては日本語のパスが読めないことがあるためです。
- 画面に出す日本語のコレクション名（「幻想肖像画美術館」など）は
  `src/main.js` の `CHAR_COLLECTIONS` が持っています。フォルダ名とは別物です。
- `original/` の元画像は**残しておくことをおすすめします。** 盤面や駒を大きくしたときに
  Web用ファイルを作り直せるためです。ただし公開リポジトリには含めないほうが軽くなります
  （`.gitignore` の `# assets/pieces/*/original/` のコメントを外すと除外できます）。

### 新しい駒を追加する手順

**入れる側の作業は「`assets/pieces/` に元画像を置いて、コレクション名を伝える」だけです。**
残りはこちら（Cowork側）でまとめます。

1. `assets/pieces/` の直下に元画像を置く（ファイル名は日本語のままで構いません）
2. どのコレクションに入れるか、フォルダ名を伝える（例：`fantasy-museum` に追加／新規に `xxxx` を作る）
3. こちらで次を行います
   - コレクションのフォルダと `original/` を作る
   - 元画像を 176×176px に縮小し、半角英数字のファイル名で Web用ファイルを作る
   - 元画像を `original/` へ移す
   - `src/config.js` の `LB.PIECE_CHARACTERS` に絵柄を足す
   - 新しいコレクションなら `src/main.js` の `CHAR_COLLECTIONS` にも足し、
     「キャラクター紹介」枠のドロップダウンに出るようにする
### 駒の寸法

駒は SVG の中で次のように組み立てています。数値は `src/ui.js` の先頭にまとまっています。

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `PIECE_ART_R` | 32 | 絵柄の半径。メダリオンはこの91%ほどを占める |
| `PIECE_RING_R` | 29.6 | 陣営の色のフチを描く円の半径 |
| `PIECE_RING` | 2.8 | フチの線の太さ（ぼかすので細くてよい） |
| `PIECE_R` | 31 | 画像が読めないときの代替の円の半径 |
| `HP_BADGE` | x18 y18 / -28° / 1.3倍 | HPの絵筆バッジの位置・傾き・大きさ |
| `ENTRY_R` | 28 | ループ入口の輪（駒より内側なので、駒が乗ると隠れる） |
| `MARK_SEL_R` | 33 | 選択中の騎を囲む破線リング |
| `MARK_CHARGE_R` | 34.5 | ループ突撃できる敵を囲むリング |

PC（盤面605px）での実寸は **絵柄 63.6px**、HPの数字 14.9px。
フチは `feGaussianBlur`（`stdDeviation` 1.2）でぼかしてあり、
メダリオンの外側に**色が分かる程度の淡い縁取り**として出ます。

HPの絵筆バッジは、`feTurbulence` + `feDisplacementMap`（`lb-brush-rough`）で輪郭をずらし、
さらに `BRUSH_STREAKS`（破線の細い線）を重ねて、絵の具がかすれた質感を出しています。

> **交点の間隔は70ユニット**です。円形のリングは半径35を超えると隣の駒と重なります。
> いまは メダリオン29.1 < 入口の輪28（駒の下） < 選択リング33 < 突撃マーク34.5 < 上限35。
> **ループ入口の輪は駒に隠れます**が、駒を選べば突撃できる相手にマークが出るので判別できます。
> 絵筆バッジは斜め45度方向に出るため、円の上限（35）を少し超えても隣とはぶつかりません。
### 絵柄そのものを作るとき

- **正方形・背景透過のPNG**で作ってください。Web用は 176×176px に縮小します。
  SVG でも構いません（`viewBox="0 0 176 176"`）。
- 円形のメダリオンは**画像の幅の約91%**を占めるように描くと、陣営のフチにちょうど接します。
  四隅は透過のまま残してください。
- 1ファイル 100KB 以下が目安です（6枚同時に読み込むため）。
- 元ファイルから Web用ファイルを作り直すときは、PowerShell で次を実行します
  （`元.png` と `出力.png` を置き換えてください）。

```powershell
Add-Type -AssemblyName System.Drawing
$b = New-Object System.Drawing.Bitmap "元.png"
$d = New-Object System.Drawing.Bitmap (176, 176, [System.Drawing.Imaging.PixelFormat]::Format32bppArgb)
$g = [System.Drawing.Graphics]::FromImage($d)
$g.InterpolationMode = [System.Drawing.Drawing2D.InterpolationMode]::HighQualityBicubic
$g.DrawImage($b, (New-Object Drawing.Rectangle 0, 0, 176, 176))
$g.Dispose(); $b.Dispose()
$d.Save("出力.png", [System.Drawing.Imaging.ImageFormat]::Png); $d.Dispose()
```

### 駒の上に重なるもの

| 要素 | 位置 | 内容 |
| --- | --- | --- |
| `piece-ring` | 絵柄の外周 | 陣営の色のフチ（絵柄の**下**に敷き、ぼかしてある） |
| `piece-hp-brush` / `piece-hp` | 駒の**右下** | 絵筆で斜めにひと塗りした背景＋残りHPの数字 |
| `piece-label` | 駒の下 | 騎の名前（A1／B2 など） |

HPは**駒の右下**に、陣営の色で斜めにひと塗りした絵筆バッジとして出しています。
筆の形は `src/ui.js` の `BRUSH_D`（本体）と `BRUSH_HL_D`（明るいスジ）で、
どちらもSVGのパスなので拡大してもぼけません。
中央に数字は出しませんので、絵柄の中央に模様を入れても問題ありません。

画像が読み込めなかった場合は、自動で**陣営の色の円**に戻ります（ゲームは続行できます）。

## いま入っている画像

### `board/frame-gold.png`（920×940px・783KB）

盤面を囲む額縁として**ゲーム本体が読み込んでいる**唯一の画像です。
`src/style.css` の `.artframe` から `border-image` で使っています。

`reference/frame1.png`（983×1385px の縦長）から作った派生素材で、次の加工をしています。

1. 左右のレールから帯を2本（402〜591行目・840〜1028行目、計379px）抜いて縦を詰めた
   → 開口部が 631×630px の**正方形**になり、正方形の盤面に合うようになった
2. 継ぎ目は前後40行かけてクロスフェードさせ、線が出ないようにした
   （中央の飾りが上下・左右の中央に残るよう、抜く位置はボスの上下に振り分けている）
3. 外周の透明な余白を切り落とした（帯の太さ：上174 右146 下136 左143px）

### `board/frame-gold-hi.png`（1380×1410px・2.4MB）

上の素材を高品質バイキュービックで1.5倍に拡大しただけの高精細版です（シャープ処理はかけていない）。
`@media (min-resolution: 1.25dppx)` の中だけで指定しているので、
**等倍の画面は読み込みません**（Windowsの拡大表示125%以上やRetinaの画面だけが取りに行きます）。

`border-image-slice` は等倍版の1.5倍で `261 219 204 215`。
等倍版を差し替えたら、この高精細版も同じ手順で作り直してください。

**別の額縁に差し替えるとき**は、中央が透明なPNGを用意し、同じように開口部を正方形にしてから
`border-image-slice` の4つの数値と `--fw` の係数を新しい寸法に合わせてください
（詳しくはプロジェクト直下の `README.md`「画面のデザインについて」）。

## 公開するときの注意

このフォルダは GitHub リポジトリに含まれ、**公開URLから誰でも見られる状態**になります。

- **他のゲームやサイトから持ってきた参考画像は、そのまま公開リポジトリに置かないでください。**
  著作権の問題になります。手元だけで参考にする場合は、リポジトリへアップロードしない
  （`.gitignore` に `assets/reference/` を追記する、または別フォルダで管理する）のが安全です。
- 自分で描いた画像・権利を持っている画像・ライセンスが公開を許している画像だけを置いてください。
- 生成AIで作った画像を使う場合は、利用しているサービスの規約を確認してください。
